# プロダクトバックログ

アジャイル運用のためのバックログ。スプリント計画時に上から順に検討し、着手時に GitHub Issue 化する。
優先度: **High**（次スプリント候補） / Mid / Low

## 機能

| 優先度 | エピック | 内容・メモ |
| --- | --- | --- |
| High | 入金・出金 | デモ用ウェルカム残高を廃止し、銀行口座からの入金/出金に置き換える（`handle_new_user` の初期残高 insert を削除） |
| High | 送金履歴の強化 | ページネーション・期間/通貨フィルタ・検索 |
| High | 冪等キー | 送金 API に `Idempotency-Key` を導入し、二重送信を防ぐ |
| Mid | 為替変換送金 | 異なる通貨間の送金（レート取得 API・手数料設計が必要） |
| Mid | QRコード送金 | ユーザーIDのQR表示・カメラ読み取りで宛先指定 |
| Mid | 送金依頼（請求） | 「○円ください」リンク/通知を送る |
| Mid | 連絡先帳 | よく送る相手の登録・表示名のニックネーム化 |
| Mid | プッシュ通知 | 受取時の通知（FCM。ネイティブ展開と同時に） |
| Low | 定期送金 | 毎月の自動送金 |
| Low | 多言語対応 | 英語 UI（intl の ARB 化） |

## 非機能・セキュリティ（銀行品質に向けて）

| 優先度 | 項目 | 内容・メモ |
| --- | --- | --- |
| High | 送金限度額 | 1回/1日あたりの上限。DB 関数内でチェック |
| High | 監査ログ | 全操作の追跡可能性（別テーブル + 変更不可権限） |
| High | レートリミット | API への回数制限（IP・ユーザー単位） |
| Mid | 2要素認証 | Supabase Auth の MFA（TOTP）を有効化 |
| Mid | KYC / eKYC | 本人確認フロー（外部ベンダー連携） |
| Mid | 不正検知 | 異常パターンの検出・一時凍結 |

## 技術・開発体験

| 優先度 | 項目 | 内容・メモ |
| --- | --- | --- |
| High | 本番デプロイ | フロント（Vercel 等）+ バックエンド（Render 等）+ ステージング環境 |
| High | フロントエンドのテスト | widget test / E2E（Patrol・integration_test） |
| Mid | ネイティブアプリ化 | `flutter create --platforms ios,android` でモバイル展開、ストア配布 |
| Mid | 状態管理の整理 | 画面が増えたら Riverpod 等を導入 |
| Mid | 依存関係のロック | pip-tools / uv によるバージョン固定 |
| Low | OpenAPI クライアント生成 | バックエンドのスキーマから Dart クライアントを自動生成 |
